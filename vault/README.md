# TruSoma Discourse Graphs vault (phase 1 of companion/DM_CONVERSION_PLAN_2026-11-15.md)
Authored source (phases 1 to 3) of the 171 learner values, the 928 body values and the 844 other values (Claims), their Evidence and the paper register (Sources), the method and join records (Claims), the audit log (Issues) and the remaining authored tables (Records, one row per note, in the property data). Everything else in the repository derived from them is generated by tools/dm/build_from_vault.py and checked in the pre-commit build step; never edit a generated file. Notes use frontmatter with one JSON value per line; titles are derived from the properties (tools/dm/readable.py: what the source says, with the key and value in brackets; a setting with no source is a "PAR - key" note), and the stable name is in the property dg_name. Node ids are deterministic and come from the stable name, not the title (tools/dm/dmlib.py). Fresh clone, in this order: (1) put the Discourse Graphs plugin files in place but do not enable the plugin yet (or close Obsidian), (2) run `python tools/dm/schema_tool.py install`, (3) enable the plugin. Step 2 writes the vault's node types, relation types and triples, with the vault's own ids, into the plugin settings. Do not use the plugin's "Import discourse graph schema" command for this: it keeps the plugin's default ids for Question, Claim, Evidence and Source, and the notes of those types would show as unknown. Meta/dg-schema-trusoma.json is the same schema in the plugin's export format, for reading. Obsidian workspace state (.obsidian/) is not committed.
Change a value: edit the Claim or Evidence note, run `python tools/dm/build_from_vault.py write` (writes every generated file: the two configurations, the links, register, audit log, records and tables), `python tools/dm/validate_vault.py`, then add the appendix [V] line and the code tag by hand as before (plan section 3c).
